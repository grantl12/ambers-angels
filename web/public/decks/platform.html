Cascade Inference Engine

Three independent signals.
A single uncertain read never fires an alert.

OpenALPR, YOLO vehicle classification, and a multi-frame aggregation window must all agree before anything reaches a coordinator. Plate-only systems miss the vehicle — we require both.

Signal 1

OpenALPR

Plate text + confidence score. Highest-frame weighted (50%), mean (30%), median (10%), plus repetition bonus and quality penalty for blur / partial reads.

→
Signal 2

YOLOv8-nano

Vehicle body type and dominant color classification. Up to 7 additional confidence points when color and body type match the FEMA alert profile. Both signals must agree.

→
Aggregation

5-second window

Groups detections by drone and plate prefix. Fuzzy matching handles OCR confusions: O↔0, B↔8, Z↔2, S↔5. Composite score computed across all frames in window.

→
Decision

Composite score

HIGH_CONFIDENCE fires Discord + optional SMS. PROBABLE triggers the Claude Haiku detection agent for secondary evaluation. Below PROBABLE: no event, no alert.

≥ 85%

HIGH_CONFIDENCE — requires ≥ 3 frames. Discord alert fires immediately. Golden evidence frame saved. Optional Twilio SMS dispatched.

75–85%

PROBABLE — requires ≥ 2 frames. Claude Haiku agent evaluates: active alerts nearby? Recent detections? Confirm or dismiss.

Privacy by Topology

Enforced by architecture.
Not by policy.

The system cannot surveil — not because we've written a policy against it, but because the data path doesn't permit it. Non-matching frames are deleted on processing, never written to disk.

🚫

No frame archive

Non-matching frames pass through RAM for inference and are deleted immediately. No video stored, no mass plate logging, no accumulation of innocent drivers' data. Between active alerts, the inference pipeline is completely idle.

🔒

Background mode: frames never leave the phone

ScanService runs ML Kit OCR entirely on-device. Only plate text and confidence score are transmitted — never the image. This is the default mode for most volunteers, and this guarantee is architectural, not configurable.

📋

Watchlist: government alerts only

The watchlist is populated exclusively from active FEMA IPAWS and NCMEC government alerts. The system never builds its own plate sightings database. A plate not on an active alert is never stored.

📁

Evidence retained, surveillance never

When HIGH_CONFIDENCE fires, one golden evidence frame is saved as chain-of-custody documentation — attached to the coordinator alert, stored with the detection record. Telemetry purges at 90 days. Detection records at 1 year. That's the full retention surface.
